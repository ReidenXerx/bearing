# North-stars — bearing

**This file is AUTHORITATIVE.** It outranks every other doc, comment, and any agent's own inference.
When a source conflicts with a north-star, **the north-star wins and that source is stale** — say so
rather than silently averaging the two.

**Cite the `NS-#`** when you make a consequential claim, choose a direction, or reject an idea. If
you can't cite one for a load-bearing conclusion, **say you may be drifting**. Never edit this file
silently — propose the change.

IDs are stable and never reused: commits and docs cite them. A retired id leaves a tombstone.

---

## Invariants — must always hold

- **NS-1** — **This code runs inside other people's repositories.** Every `writeFileSync`, `rmSync`, `unlinkSync` and `renameSync` acts on work someone else cannot get back. Before any of them, ask: what if this runs twice, what if it half-fails, what if the target already exists, and what if the user put that file there? Uninstall once deleted the user's north-stars because `.bearing/` *looked* kit-owned.
- **NS-2** — **A core module may NEVER depend on a feature module.** Features are independently installable, so a core→feature edge breaks core whenever that feature is absent. The invariant is COMPUTED (`coreLibClosure()`), not hand-maintained — it silently broke twice as a list. The closure must follow static imports, dynamic `import()`, **and child-process spawns**, while ignoring JSDoc type references.
- **NS-3** — **Install and update must be idempotent.** Running either twice, or install-then-update, must converge: one gitignore block, one hook registration per event, no duplicated scripts. Anything that accumulates is a defect.
- **NS-4** — **Migration runs BEFORE the bundle copy.** Any migration step that inspects the TARGET for something the copy step provides is a no-op on first run. Check the BUNDLE instead. This shipped once and required two updates to take effect.
- **NS-5** — **Never block work to force a tool — when a guard is unsure, it says nothing.** A false deny is worse than a missed gate: blocking legitimate work, with advice the user cannot follow, destroys trust faster than letting one grep through. Measured across the fleet (36 sessions, 2026-08 → 2026-11): 1,212 grep/read redirects against 1,246 graph calls, and of 169 written fallback reasons, 51% were questions the graph had never indexed. Anything that still blocks must name its exit in the block itself — enforcement that cannot be escaped is a trap. *Amended 2026-11-06: absorbs NS-6. The exits it named, `bearing:fallback` and `mode: guide`, stay as aliases (NS-15) but stop being the design (NS-25).*
- **NS-7** — **Hooks run on every tool call.** Nothing on that path may read a whole file, spawn unnecessarily, or block without a bound. Prefer a bounded scan that stops early over a correct-but-linear one.
- **NS-8** — **Fail open on the hot path, fail closed on the graph.** An unreadable file, malformed JSON or missing stdin must never block the developer; a stale or missing index must never be reported as fresh. "Closed" means the answer carries how stale it is — never that the answer is refused. *Not holding as of 2026-11: 18 fallbacks were staleness reporters contradicting each other or the CLI right after a successful refresh.*
- **NS-22** — **Only a FIRST install can observe what the user owned.** Every "was this here before us?" question — is the `.gitignore` ours, did we add `engines.node`, was there a `.cursor/hooks.json` — must be answered once and RECORDED in the manifest. Re-deriving it later reads our own artifact as the user's, because by the second run the file exists *precisely because we wrote it*. Three fields have hit this: `createdGitignore`, `addedEngines`, and `backups` — the last made uninstall restore bearing's own Cursor hooks, registering scripts the same uninstall had just deleted. An earlier install's answer is the authoritative one. Record it **per adapter**, since a runtime added later (claude first, then cursor) meets a genuinely user-owned file for the first time.

- **NS-23** — **bearing ships JUDGMENT, not capability.** Every agent can already review code, spawn subagents, adopt a persona, read a doc. What none of them know is **WHEN** — a milestone is when to review with a panel, a 40-site trace is when to fan out, a compaction is when the goal gets lost. So a proposal that adds a capability the agent already has is not a feature; **the trigger is the feature**. Microscope is not "we can review", it is "review HERE, this way". Judge every module by whether it changes what the agent DOES at a moment it would otherwise have handled worse — and if you cannot state that moment in one sentence, there is nothing to ship. GitNexus is the module that taught this the hard way: forcing the graph on every search was capability, not judgment (NS-28), and guessing the moment for it failed too (NS-29) — so the trigger is the user asking (NS-25). **Where the user is the trigger, the method is the feature.** Microscope and minions are invoked by the user ("microscope this", "fan this out"): bearing ships HOW, never WHEN, and never pushes them. Measured: the hard round (`eval/intel/REPORT-HARD.md`) never saw an unprompted agent need either at 200 files and 106 sites, and the push cost 1.5–2× per task. Judge such a module by whether, once invoked, it does the job better than the agent's own way. *Amended 2026-11-12, approved by the user: the examples above (a milestone, a 40-site trace) were the triggers bearing fired for microscope and minions until #40; both are user-invoked now.*
- **NS-24** — **Delegated work EXECUTES a decision; it never makes one.** A subagent does MINIMAL OR ZERO REASONING, in one of two shapes: it GATHERS and returns what it saw — `file:line`, verbatim output, the exact query it ran — or it APPLIES a transformation decided in full beforehand and returns what it wrote. Never a verdict, never a choice. Reasoning is precisely where an agent holding less context than you drifts, so a subagent that DECIDES inserts an unaccountable choice between the evidence and the outcome, and the fan-out becomes a drift AMPLIFIER — the opposite of this product. **Wanting a smarter subagent is the tell that you delegated a decision**; the fix is the brief, never the model. A report must separate "looked and found nothing" from "never understood the task" — and, when applying, "changed it" from "found a shape the brief did not cover"; collapsing either is the same failure as reading a graph zero as absence. *Amended 2026-09-07: the original said "delegated work GATHERS", which named the proxy rather than the hazard. Applying a decided change is not concluding, and the invasive-minions module was reinterpreting this in a skill instead of proposing the change here.*

## Semantics — exact meaning here

- **NS-26** — **"The index" is one checkout at one commit — not the repository.** Linked git worktrees, PR refs and other branches, other repositories, uncommitted files, `node_modules`, `.e2e/` and bearing's own `.bearing/` are invisible to it, and a lookup there returns "not found", which reads exactly like absence. Anything that points an agent at the graph checks scope FIRST and stays silent outside it. 87 of 169 fallbacks were this; 55 came from one repo's worktree workflow, where every search was redirected to a graph that had never seen the code.

## Evidence — what counts as proof here

- **NS-9** — **A passing test proves nothing until it can fail.** Four defects shipped underneath green tests: a vacuous assertion (a path that could not exist post-rename), a convenient fixture (the replacement pre-created, hiding an ordering bug), a wrong harness shape (`tool_name` vs `tool`, silently hitting an empty-input branch), and a "runs without crashing" check blind to silent degradation. **Revert the fix and watch the test fail** before believing it.
- **NS-10** — **Verify by executing, not by reading.** Every real defect this project has found came from running the thing — a real install, a real upgrade with real data, a rasterized SVG, a packed tarball installed as a consumer. Reading the code found none of them.
- **NS-11** — **An unexpected result is a finding, not a nuisance.** Twice a "fix" changed output in a way I nearly rationalised: the core closure gaining `classify.mjs` (a JSDoc false positive) and a shell gate that went quiet (a `ReferenceError` swallowed into blanket allow). If output moves in a way you did not predict, stop.
- **NS-12** — **Test the negative case.** A gate is only proven by asserting that something IS denied — the shell gate opened completely and every allow-assertion still passed. A nudge is only proven by asserting it stays SILENT where it cannot help: an out-of-scope path (NS-26), a string literal, a file the index never saw. A nudge that fires everywhere teaches the agent to skip it.
- **NS-20** — **Every line the installer prints is a CLAIM, and an unchecked claim is a lie waiting to happen.** Nine defects reached a real machine in one session and the existing verifier caught zero, because it asks "does this file exist" and every one of them had the right files with the wrong CONTENT. Three printed success while broken: the macOS service announced `listening on 127.0.0.1:39100` for an agent crash-looping on exit 127, the CLI exited 0 having installed nothing when its path crossed a symlink, and all 16 npm scripts silently reverted to `npx gitnexus@latest` after the installer had just written the operator's choice. **Presence is not correctness.** Assert post-conditions against the disk (`lib/postcheck.mjs`), never behind `--skip-verify` — that flag exists to skip the slow index build, and every automated path passes it, which is exactly how these shipped. A failed check must change the headline and the exit code, not sit above a green "Install complete".
- **NS-21** — **The least-exercised configuration is the least verified, and that is backwards.** `scripts/bearing-verify.mjs` and its fallback lib are both owned by the gitnexus feature, so an intel-only install — the configuration the author never runs — had no verification at all. Checks that must hold for every install belong in `lib/`, outside the feature axis.
- **NS-27** — **Count what changed, against an answer key the graph did not write.** An interception is not a result: a redirect, a gate or a nudge proves only that a hook fired — `bearing:stats` printed "86 lazy-search redirects" as value while unable to tell a helpful redirect from a false deny. Measure what the agent did next and whether it was right. And ground truth for any graph eval is hand-verified, never derived from the index: a benchmark graded against a "graph-derived closure" cannot see the graph being confidently wrong — which 41 of 169 fallbacks were, often marked `epistemic: "exact"`.

## Settled — decided; do not relitigate

- **NS-13** — **GitNexus is one module, not the product.** The intel layers (north-stars, task-core, microscope) have no GitNexus dependency and must keep working without it. Never let graph wiring — gates, nudges, contract text — leak into a repo that declined the module: not via files, hook registration, npm scripts, or `.mcp.json`. All four channels re-introduced it once.
- **NS-14** — **Only Claude Code gets the timing; every runtime gets the content.** Moment-triggered behaviour — a gate, a nudge, a re-anchor — needs tool-interception hooks, and since Cursor's removal in 1.2.0 exactly one runtime has them. Zed, Codex and Warp's Oz get the contract and skills and nothing else, and the README says so plainly — overstating parity is the fastest way to lose a first-time user. So what an agent must KNOW (when the graph wins, where it is wrong) lives in the contract, where every runtime reads it; hooks only decide WHEN to say it. Two consequences are not optional: hook behaviour is a single-runtime feature, so its tests are the only proof it works (removing Cursor deleted the proof, not the behaviour); and every intel module must work with no hooks at all. *Amended 2026-11-06: was "Only Claude Code can enforce", framed around gates (NS-25).*
- **NS-15** — **Legacy names stay as aliases.** Renaming broke nothing because every `gitnexus:*` script still resolves; user-owned git hooks invoke them BY NAME. Any future rename carries the same obligation.
- **NS-16** — **The product is described in three places** — `package.json` (npm), `README.md` (GitHub), and the GitHub About box — and nothing keeps them aligned. A test enforces the first two against the code; `npm run sync:meta` pushes the third. They drifted for real.
- **NS-19** — **The context window is not knowable at runtime — never gate behaviour on a percentage of it.** The transcript does not record it; the model id does not settle it (`claude-opus-5` is the same string on a 200k session and a 1M one); and the only real measurement, `compactMetadata.preTokens`, arrives *after* a compaction has already happened. Two attempts at inferring it shipped and were wrong in opposite directions: a hardcoded 200k made every 1M session read as 300% full, and the correction for that could not reach the band it was written for — it announced "compaction is near" at **19.7% full** on a live session. A gate on an unmeasurable number produces confident false alarms, and a false alarm is worse than no alarm (NS-5). **Trigger on what can be counted instead** — work done since the last save, not fullness. The task-core nudge counts EDITS since the core was written, because what makes a compaction expensive is unwritten work, not occupancy. Retired with this: `contextWindowTokens`, `contextPressureThreshold`, `contextCheckpointEvery`, `GITNEXUS_CONTEXT_WINDOW`, `context-pressure.mjs`. Do not reintroduce a percentage-of-window trigger without a measurement that arrives BEFORE the compaction it is meant to precede.
- **NS-17** — **npm renders neither mermaid nor relative-path assurances.** Diagrams are generated SVG served over absolute raw URLs (`npm run gen:diagrams`). Do not reintroduce mermaid into the README.
- **NS-31** — **bearing is a toolbelt for developers who already work with coding agents, not training wheels.** The user decides WHEN; a tool ships its method and its traps (NS-23, NS-30). bearing speaks up unasked only about what neither the user nor the agent can see from inside the session (drift across a long context, unsaved work before a compaction), and each such moment has a named knob that turns it off. A feature whose purpose is to make someone follow a workflow they didn't choose is out of scope. — src: user, 2026-11-12
- **NS-25** — **GitNexus is opt-in and user-invoked.** bearing ships no gate, no teaching moment and no always-on instruction for the graph. It is installed only when asked (`--features +gitnexus`, or a yes to the installer step that explains what it is), and used when the user asks for it; one skill, `bearing-gitnexus`, carries how to use it well — scope first (NS-26), where it wins, where its count is a floor. Evidence: a 180-run eval on a fixture with hand-verified answer keys — the gates cost 4–5× per solved task for one task’s gain; teaching moments almost never fired; contract-only guidance changed behaviour once (`rename`). *Rewritten 2026-11-06: was "taught at the moment it wins, never forced" — the moments were tried and rejected (NS-29).*

## Graveyard — tried and rejected / validated

- **NS-28** — **REJECTED: forcing graph-first by blocking Grep, Read, Bash and Edit.** Tried from the kit's first release to 2026-11. Across 36 sessions it produced one redirect per graph call; in one repo 26 redirects led to 2 graph calls; the classifier grew to 1,004 lines, most of its 32 allow branches carve-outs from its own 19 denies; and it reached one runtime of four (NS-14). Re-propose only with evidence that addresses scope (NS-26) and the confidently-wrong code shapes (NS-25).
- **NS-29** — **REJECTED: moment-triggered teaching of the graph (M1–M6).** Tried 2026-11. Across 60 eval runs it produced ~0 graph calls: the moments were tied to actions (an edit, a commit) while the graph wins on questions ("what does this change affect?"), and real searches — `git grep -nE "a|b"` through Bash — never matched the search moment. It cut cost 36–43% against the gates but still ran 2.4–3× the no-kit cost, mostly the always-on contract. Re-propose only with evidence that a moment FIRES and is TAKEN (NS-27), on a repo large enough that grep is not free.
- **NS-30** — **VALIDATED: a tool gets used when the contract says WHEN and a skill carries its traps — not when a moment interrupts.** ast-grep, taught by one contract section and a skill, was used in 9 of 9 runs on a real 650-file repo; the graph, taught by moments (NS-29), got ~0. **Adoption is not benefit:** the same round made agents WORSE on a question about bindings until the skill said when NOT to use the tool (0/3 → 3/3). Measure both, against a key the tool did not write (NS-27). — src: eval/intel/REPORT-REAL.md
- *(NS-6 retired 2026-11-06: "every block must have a discoverable exit" is now a clause of NS-5.)*

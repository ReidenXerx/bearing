npx bearing · a toolbelt for coding agents, for people who already use them

Your tests catch code that breaks. Nothing catches an agent that has drifted.

A drifted agent doesn't crash. It reads a doc you abandoned in March, re-proposes the feature you already measured and killed, and writes a convincing paragraph about it. You nod. You find out three days later.

bearing is a toolbelt for developers who already work with coding agents: north-stars that outrank stale docs, memory the agent keeps true, a task-core that survives compaction, ast-grep with the traps that make it lie, review and fan-out when you ask for them. You decide when.

The failure this exists for

Losing your bearings is a failure with no stack trace

Nothing is red. The build passes, the tests pass, the paragraph is convincing. What changed is what the agent believes the code means — and belief has no assertion.

Always on · maintenance

Your agent keeps its own memory true

The next session starts from memory, not from this transcript. A coding agent writes memory when it thinks of it, and nothing else keeps it current — so bearing asks it to maintain memory at the four moments it goes stale. bearing asks; the agent does the writing.

Session start

Memory is a week old, and commits have landed since

Reconcile it before trusting it.

While it works

25 edits since the task-core was last saved

Save the task again — compaction can land any time.

At a milestone

A PR merged, a tag cut, a release, a publish

Does memory still say what is true? Update it, delete what isn't.

After compaction

The transcript was summarised away

Read the task-core and memory back first, then check them against the code.

Every prompt has a knob — memoryNudge, memoryStaleDays, taskCoreEveryEdits — and npx bearing status shows how often each fired. The prompts need Claude Code's hooks; on Zed and Codex the contract still asks for it. How it works.

What you get

Sixteen modules. Pick any combination.

Each works alone and none depends on another. Seven are on by default; --features northstars,taskcore is a complete install, and so is --features all. Each card opens the module's page.

On your command

Minionsdefault

Tools, with their traps

ast-grep is on by default; the rest are opt-in. None adds anything to your package.json.

ast-grepdefault

Search and rewrite by code shape.

A pattern that does not parse returns [] exactly like a clean codebase, and -l ts skips every .tsx — so the pattern is proven on a known site first.

Git history

Why the code is this way.

The commit and PR behind an odd guard, before anyone removes it. Plain blame names the formatter; it looks past it.

knip

What is really unused.

Its list is candidates: migrations, glob-loaded entities and hand-run scripts look dead too. It tells knip without touching your repo.

mergiraf

Merges parallel work by syntax tree.

Two branches add an import and a method to the same class: git conflicts, mergiraf keeps both — and your agent reads every resolution before committing.

Rules for your stack

Opt-in, for the stack you have.

TypeScript / JavaScript

Code that compiles and is still wrong.

Numbered TS-# rules for what tsc and ESLint stay silent about: an as that verifies nothing, a union that falls through, || overwriting a deliberate 0.

Frontend

Stops the near-duplicate component.

Search by shape before building another table. An edit that changes what a shared component renders for existing callers is an ask.

React

The form bugs that fail silently.

A field owns its Controller; a name typed FieldPath<T> turns a renamed field into a compile error instead of a missing value.

Opt-in kits

Each asks before installing anything heavier: Playwright, or the GitNexus CLI and MCP server.

E2E harness

"I checked it in the browser" becomes an exit code.

Polling waits, assertions on the body, a destructive write tested without performing it — and narrated demo videos, reviewed before anyone sees one.

Publish

Visuals that make one true claim.

A card, a hero, a release header: one claim, traced to code or a measurement, rendered whole by a renderer that fails on a broken image — then looked at.

GitNexus

A code graph, only when you ask.

Opt-in: the installer explains it and asks. Say "use gitnexus" and one skill loads — scope first, where the graph wins, where its counts are a floor.

North-stars

Falsifiable, or it's decoration

Docs rot. Comments lie. The agent's own inference fills the gaps — confidently. A north-star is a numbered claim about what your project is, written so that a conclusion could actually violate it.

"Be careful with risk" can't be violated, so it can't catch anything. The graveyard is the half people skip: an idea that was measured and killed stays killed until new evidence shows up.

If the agent can't cite a north-star for a load-bearing claim, it says so. That sentence is your drift alarm.

.bearing/northstars.md

- NS-4 — Win-rate is NEVER a ranker. Only net
         expectancy is a profitability claim.

- NS-9 — REJECTED: averaging into a losing
         position. Measured: adds fill only on
         the weaker cases. Don't re-propose
         without new evidence.

Gold practices — the half that isn't yours

North-stars say what your project is. gold-practices.md ships with bearing and says how the work is done anywhere — numbered GP-#, cited the same way, and outranked by your NS-# whenever they disagree. Every rule carries a scar, and a rule without one is not in the file.

GP-3 — Test at the seam the bug lives at. A unit test that passes an argument the real pipeline never produces is green and dead. Scar: a context-window fix tested as resolve(300_000, undefined) while the shipped config always passed a number — so the fix could not run, and did not, for two releases.

Where it fires by itself

Nudges need hooks, and not every runtime has them

Only Claude Code exposes tool-interception hooks, and an empty cell is not always absence: the task-core skill and its contract section install everywhere, so you can invoke it by name — what Claude Code adds is the nudge that fires it unprompted. On ask means it never fires by itself, by design, and answers when you ask. Minions need Claude Code's subagents and are not there at all where the column is empty.

Install

One command, and it explains each module before it writes anything

$ npx bearing
# interactive — explains each module

$ npx bearing install . \
    --runtime claude \
    --features northstars,taskcore

# or take the lot
$ npx bearing install . --features all

# later
$ npx bearing update .      # keeps your choices
$ npx bearing uninstall .   # restores what it overwrote
$ npx bearing status        # what it loads, what speaks up + its knob
$ npx bearing doctor        # is the install healthy

Node ≥ 22.9.0 · a git repo · macOS, Linux, Windows or WSL. The GitNexus module additionally needs the GitNexus MCP server. Then restart your IDE.

Contributing to a repo that isn't yours?

A normal install is a team decision: hooks, skills and a contract, committed, and everyone who pulls gets them. That is right for a repo you own and wrong for one you contribute to.

$ npx bearing install . --stealth

Stealth makes one promise, and it is testable: git status is exactly as clean after the install as it was before. Ignores go in .git/info/exclude, which is per-clone and untracked, so the rules can't travel. It refuses to convert a repo where bearing is already committed — un-tracking it for your whole team is a deliberate, visible act.
